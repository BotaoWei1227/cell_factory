# 無限煉製配方樹

## 網頁版

GitHub Pages 網頁版可輸入目標造物、已有材料與搜尋範圍，直接顯示最短合成樹，也能複製文字樹或下載 JSON。

由於遊戲的公開 API 未提供跨網域權限，網頁版預設透過公開 CORS proxy 讀取資料。它只會傳送要查詢的公開造物名稱與公開 API URL；若 proxy 暫時不可用，可在「連線設定」替換為你信任的 proxy，或自行部署同網域 API 代理。

部署到 GitHub 後，workflow 會自動發佈至 GitHub Pages。

## 命令列版

`recipe_crawler.py` 會從遊戲的公開 API 讀取配方，遞迴往上追溯每一個原料，並在所有已爬到的配方中選出最短的完整合成樹。

它是唯讀工具：不需要登入、不會按下遊戲的「煉製」按鈕，也不會寫入遊戲帳號資料。

## 執行

需要 Python 3.10 以上，且不需安裝額外套件。

```powershell
python .\recipe_crawler.py 機器人 --max-depth 5
```

若使用者已擁有特定原料，將它們列在 `--owned` 後方；這些材料的合成成本會視為 0，結果就會是對該使用者最短的路徑：

```powershell
python .\recipe_crawler.py 機器人 --owned 鋼鐵 AI晶片 人 --max-depth 7
```

輸出會寫進 `output/`：

- `機器人-shortest-tree.txt`：容易閱讀的樹狀圖。
- `機器人-shortest-tree.json`：完整結構化結果，方便日後接前端或做可視化。

## 最短路徑怎麼選

一個造物常有多條 `A + B → 目標` 配方。程式會對每條配方的兩個原料都繼續追溯，並依序選擇：

1. 合成層數最少的樹。
2. 若同層數，優先使用 `--owned` 指定的已有材料。
3. 若仍相同，原料葉節點與總節點最少的樹。

預設只追 5 層、最多讀 300 個造物，避免像「機器人」這類熱門詞造成分支爆量。遇到 `[到達深度上限]`、`[找不到公開配方]` 或 `[略過循環]` 時，代表該分支沒有在本次搜尋範圍內繼續展開；可提高 `--max-depth` 或 `--max-nodes` 後重跑。

目前遊戲 API 回傳的是該造物可見的配方清單，因此程式會在該清單範圍內保證選出最短樹；之後若網站改變 API 或分頁規則，需再調整資料讀取層。
